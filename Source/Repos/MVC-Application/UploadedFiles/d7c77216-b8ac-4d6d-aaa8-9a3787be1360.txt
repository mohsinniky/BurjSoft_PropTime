- It is an open Source O/RM (Object-Relational-Mapping) Framework

- It saves time by automatically handling the database operations (like insert, update, delete, fetch)
- Developers don’t have to write a lot of data-access code.

- Model View Class:

- DTO
	- Data Transfer Objects
	- a design pattern that gives flexibility
	- transfer data independently between different Layers
	- to maintain a clear separation between different layers of the application
	- increasing Code readablilty as only having attributes and no business logic
	- for loose coupling

- 3 Layer Architecture
	- Also known as 3 tier Architecture
	- A way of Structuring your Application into 3 seperate layers
 	- to seperate responsibilities so that the code is easy to understand
	- Layers:
		- Presentation Layer
			- The top Layer that interacts with the user
			- Accept Input from User, Send the input to business layer for processing, Show result to the user
			- Classes/Files: Controllers, Views, API endpoints(a specific URL, serves as a point for applications to access resources from a web service.)
		- Business Layer
			- Middle Layer , that contains the Main Logic
			- Process input from the Presentation Layer, Apply (B_rules, Validations, Calculations),Decide what Data to Fetch/Update but not HOW.
			- Classes/Files: Service, Managers
		- Data Access Layer:
			- The bottom Layer that talks to the Database
			- implemented with EF_Core, Dapper or ADO.net
			- Role: Interact with DB for CRUD, Sending Data data back to Business Layer
			- Classes/Files: Repositories

- AsTracking:
	- A method, in EF Core that tells the EF to track Changes made to the data it loads from the database
	- Method added during QueryFormation(In DAL),

	- When query Executed , by default the Tracking is Enabled
